## 1. Contradictions resolved

### 1.1 Name: extend `shell_exec` in place (tracks 1 + 3), not a new `command_exec` (track 5)

Track 5's argument for a new name was that an additive name gives a green intermediate state. That is real, but extending `shell_exec` is *also* purely additive — new optional parameters only — so there is no intermediate red state to avoid. Against a new name: `cyber_os/assets/tool_map.py:33` maps `Bash -> shell_exec` for all 68 markdown specialists, `cyber_os/compaction.py:51` special-cases the literal, `cyber_os/subagents/profiles.py:108,125` grant it and `:239` maps it to `DIAGNOSTIC_TERMINAL`, and the AST test scans literals. A rename edits five consumer classes for zero capability.

Taken from track 5 regardless: its **ordering discipline** (relax assertions first, land the safety replacement before any removal, migrate callers while both states are valid, one atomic removal commit).

One correction to track 1: the registration must **not** stay in `Tools_cyber`. Register `shell_exec` as a mandatory, first-class entry in `register_all_default_tools`, built from a single shared implementation that receives the agent's `audit_logger`, `cancel_event`, `_publish_ui_event`, `default_distro`, `_extract_scan_progress`. Keep `Tools_cyber/shell_exec.py` as the degraded standalone path for `CyberToolsClient` only, and make the plugin adapter **skip registration if the name is already registered** (rather than relying on implicit last-writer-wins through the bare dict assign at `cyber_tools.py:522`). Assert at startup that the winner is the agent-bound implementation.

### 1.2 How many wrappers survive: **zero CLI wrappers, one surviving tool name**

Tracks disagreed: discoverability said 59 → 0 (+1 catalog), unified-command said 59 → 0 (−`pty_run`, +`shell_recipes`), migration said 58 → 0 with `windows_defender_scan` kept.

**Decision: delete all 59 CLI-wrapper registrations. `windows_defender_scan` survives as a *name* only, backed by the already-existing `WindowsDefenderAdapter.scan` python_func — so the count of pure CLI wrappers goes to 0, and the count of surviving names is 1.**

Justification, and it is a capability argument, not a naming one:
- `tool_orchestrator.py:1288` (`if tool_call.tool == "windows_defender_scan": for threat in result.get("threats_found", [])`) is the only path that converts a Defender detection into a critical finding. A generic command tool returning stdout loses that anchor — Defender detections stop becoming findings, which is the same failure class as the fabricated-audit-event bug the lead is already fixing.
- The adapter at `:570-578` is a real implementation that already shadows the wrapper. Keeping the name is not preservation of a wrapper; it is deletion of the *wrapper* and promotion of the *adapter*.
- It is the `fallback_tool` target of `clamav_scan` and one of only two of the 59 named in `profiles.py` (`:70`).

Every other wrapper's capability is fully expressible as a command string plus a preset row. Track 3's Fact 2 kills the case for keeping more: `is_environment_available` only answers "does WSL exist", never "is nmap installed", so a named wrapper already fails as plain stdout on a host without the binary. Named wrappers buy nothing on availability.

### 1.3 Risk model: track 2's substance, track 1's wiring

Track 1 proposed `risk_resolver: Optional[Callable]` on `ToolDefinition` with `max(profile_risk, pattern_risk)`. Track 2 proposed `risk_classifier` with per-interpreter splitters, a refuse-list, a YAML ruleset and segment-max. These are the same hook at different depths. **Take track 2's classifier as the implementation and track 1's minimal wiring: one optional field, one call site, fail closed.** Reject a static `risk_level` on the unified tool in both directions — `READ_ONLY` auto-approves arbitrary commands at `cyber_tools.py:141`, `MODIFIES_SYSTEM` converts 58 wrappers of previously silent read-only traffic into approval cards and trains operators to click through.

### 1.4 Preset risk vs. classified risk: one authority, not two

Track 3 wanted the preset's `risk_level` to reach `_wait_for_approval`; track 2 wanted the resolved string classified. Two risk paths is a bug waiting to happen. **Decision: the resolved command string is the only input to risk.** A preset earns `READ_ONLY` because its expansion matches an allowlist rule in `command_rules.yaml` with constrained flags — the same rule a hand-typed `nmap 10.0.0.1` would match. Preset values are substituted as argv elements only; there is no free `flags` parameter. Both mechanisms then agree by construction.

### 1.5 Discoverability: pushed catalog in the prompt (track 3), pulled detail in one tool

Track 1's `shell_recipes` and track 3's `command_catalog` are the same tool; track 3's additional prompt section is the part track 1 lacked, and it is the only mechanism that can carry the **absent-on-this-host** bucket. Track 2's `classify_command` dry-run is folded in as a parameter of the same tool rather than a second tool. Net: **one** new discovery tool, `command_catalog(query="", explain="")`, plus a generated prompt section replacing the stale hand-written `TOOL_RECIPES` at `cyber_os/system_prompt.py:72-82`. Reject enum-in-schema (track 3 is right: `to_manifest()` emits no `parameters` key, so there is no schema for an enum to live in).

### 1.6 Python-tool dedupe (track 4) is a separate PR, with two exceptions

Track 4's 13 merge groups are a different concern from the user's ask and would triple the blast radius of one commit. It becomes **Phase D**, sequenced after the consolidation lands.

Two items are pulled *forward* into this change because they are the same shell surface, misfiled as python tools: `service_enumeration` (`subprocess.run(shell=True)` on `Get-Service` / `systemctl`, duplicating `get_service`/`sc_query`) and `traceroute_simple` (`tracert`/`traceroute -m 30`, duplicating the `traceroute` wrapper). Both bypass env routing, the risk gate and `execute_system_command` entirely. They are deleted in the removal commit.

Also pulled forward: track 4's `file_hash` replacement, because `sha256sum` / `powershell_file_hash` / `hashdeep` / `aide_check` are four of the 58 being deleted and `aide_check`'s fallback edge points at `powershell_file_hash`. A registered `file_hash(path, algorithm="sha256", recursive=False)` wrapping the already-written-but-never-registered `IntegrityChecker.calculate_file_hash` removes a WSL dependency from the integrity path in the same commit that removes its wrappers.

### 1.7 `pty_run` is deleted, not preserved

Track 1's finding stands: it calls `self.pty_manager.get_or_create_session(...)` and `sess.execute(...)`, neither of which exists on `PtySessionManager` (which has `create_session`/`interact`, with `TerminalSession` a bare dataclass). It raises `AttributeError` on every call, and is registered `READ_ONLY` while executing arbitrary commands — an outright approval bypass under `auto_approve_read_only`. Its intent is absorbed by `shell_exec(mode="start"|"poll"|"send"|"kill")`.

`mode="run"` does **not** route through `PtySessionManager`: that class uses `shell=True` on a raw string with no env mapping and no deadline kill, while `execute_system_command` already has the `output_callback` and `cancel_event` plumbing.

### Step 2 — Land the policy layer and its tests, with nothing removed
**New files:** `cyber_os/policy/command_rules.yaml`, `cyber_os/policy/command_classifier.py`, `cyber_os/command_presets.py`, `tests/test_command_classifier.py`

**Generate the data, do not hand-transcribe it.** Write a throwaway script that walks the *live* registry before deletion and emits both the 59 preset rows (`id`, `summary`, `env`, `argv_template` from `command_template`, `probe_binary`, `fallback_preset` from `fallback_tool`, `example`) and the 59 seed rules (`binary` from argv[0], `allowed_flags` from the template's literal flags, `level` from `risk_level`, `requires_admin`). Hand-transcribing 59 risk levels is exactly where the security metadata gets silently lost.

`classify_command(command, interpreter) -> CommandRisk{level, requires_admin, reason, matched_rules, segments, undecidable, confidence, ruleset_hash}`, with four non-negotiable principles:

1. **Split first, classify every segment, take `max()`.** Never classify the prefix. `nmap 10.0.0.1; rm -rf /` must not inherit nmap's `READ_ONLY`.
2. **`READ_ONLY` is earned, never defaulted or inferred.** Unknown floors at `MODIFIES_SYSTEM`.
3. **Unparseable escalates to `DESTRUCTIVE`,** not to the middle tier. Failure to decompose is evidence of evasion, not of benignity.
4. **Match on argv, not substrings.** Reuse `cyber_os/approval_engine.py`'s existing `tokenize_command` (shlex, `posix=False`); normalize `tokens[0]` (basename, strip `.exe`, casefold); exact-key lookup. Do not repeat the anti-pattern at `cyber_tools.py:1097` (`any(op in cmd_lower for op in ["rm ", "del ", ...])`, which misses `/bin/rm`, `Remove-Item`, `"rm"`, tab-separated `rm`).

Three splitters (cmd, PowerShell, bash), each with a **refuse-list** whose mere presence pins the whole command to `DESTRUCTIVE`: `eval`, `iex`/`Invoke-Expression`, `-e`/`-enc`/`-EncodedCommand`, `bash -c`, `sh -c`, `cmd /c`, `certutil -decode`, `FromBase64String`, `curl … | sh`, `IWR … | iex`, nesting past depth N. One decode pass of `-EncodedCommand`/`base64 -d` is attempted to *inform the operator card*, floored at `MODIFIES_SYSTEM` — a decode pass can never yield `READ_ONLY`.

Two traps that survive correct splitting and need explicit rules: **argument-position execution** (`find -exec`, `xargs rm`, `nmap --script`, `tar --to-command`, `git -c core.pager`, `ssh host '<cmd>'`) — hence `allowed_flags` per rule and "unrecognized flag on an allowlisted binary drops that segment to `MODIFIES_SYSTEM`"; and **redirection** (`>`, `>>`, `Out-File`, `Set-Content`, `-oN`/`--output`) — floors at `MODIFIES_SYSTEM`, `DESTRUCTIVE` if the target resolves under a protected path. Resolve path-looking tokens against `cwd` to absolute paths and compare drives; do not substring-scan.

`requires_admin` becomes real (it is currently enforced nowhere, flowing only into `to_manifest`): OR of rule-declared, target-derived (`HKLM:`, `System32`, `/etc`, `/boot`, `/dev`, service control) and observed (`KernelPrivilegeValidator.is_privileged()`). If `requires_admin and is_privileged()`, **raise the floor one tier** — identical command, larger blast radius.

Loader **fails closed**: a malformed rules file means "no allowlist", therefore everything classifies `MODIFIES_SYSTEM`. It must never mean "no rules, allow". Record `ruleset_hash` at startup.

Also in this step: `resolve_invocation(args) -> ResolvedCommand{program, interpreter, exec_string, env_registry, preset_id, fallback_of}` — the single shared resolver used by both the classifier and the executor (see Step 4 for why).

**Gate:** new `tests/test_command_classifier.py` must contain, and pass, the regression corpus described in §4. Old suite green; registry still 207.

### Step 3 — Extend `shell_exec` in place as a mandatory registration
**Files:** `cyber_tools.py` (`register_all_default_tools`, the plugin adapter at `:2607-2623`, `execute_system_command` at `:1091-1130`), `cyber_agent.py` (hook injection)

Signature:

```
shell_exec(command="", environment="auto", preset=None, args=None, mode="run",
           timeout=None, cwd=None, stream=None, distro=None, session_id=None,
           input_data=None, max_output_bytes=65536, allow_fallback=True)
```

- `environment`: `"auto" | "powershell" | "cmd" | "wsl"`. `"auto"` resolves deterministically, no LLM guessing: preset/rule hit → that env; Verb-Noun `^[A-Z][a-z]+-[A-Z]` or cmdlet piping → powershell; known native shims (`sc`, `wmic`, `netsh`, `reg`, `tasklist`) → cmd; else powershell on win32. Explicit always wins; `environment_used` is echoed in the return and in every audit event so a wrong inference is visible.
- **Move the env-availability gate inside.** `is_environment_available("cross_platform")` returns `True` unconditionally (`cyber_tools.py:404-405`), so `execute_tool`'s outer gate is structurally dead for this tool. Keep `environments=["cross_platform"]` so the tool never disappears from the catalog on a WSL-less host, and re-check the *resolved* registry env internally.
- **The four fallback edges become `fallback_preset` rows** (`clamav→windows_defender_scan`, `rkhunter→autoruns`, `aide→file_hash`, `auditd→windows_process_monitor`). Emit the **same** audit event names `tool_fallback` / `tool_skipped` and the same message shape (`"Command 'nmap' requires wsl_linux, which is not available. Skipping."`) so downstream log queries keep working. Carry `program` in every payload — that is what preserves the per-tool signal that SIEM/report queries used to get from `nmap_scan` vs `clamav_scan`.
- **Streaming timeout watchdog, mandatory here.** In `execute_system_command` the `for line in proc.stdout` loop has no deadline and `proc.wait(timeout=timeout)` only runs after EOF; `cancel_event` is checked only when a new line arrives. Streaming becomes the common path in this design, so a silent hung process would block forever and ignore `cancel_run`. Add a deadline kill, and pass `cancel_event=self.cancel_event` — today's `shell_exec` does not, so shell commands are currently uncancellable.
- **Rewrite the protected-drive guard** (`cyber_tools.py:1093-1102`): resolve `cwd` plus path-looking tokens to absolute paths and compare drives instead of substring-matching `f:\` / `/mnt/f`, which `pushd F:\ && del x` walks straight past. Emit a `command_blocked` audit event — today the denial returns with no audit trace at all.
- **Truncation is not optional.** `strings`, `plaso`, `volatility` emit megabytes. Keep first 40 KB + last 24 KB with an elision marker, spill the full stream to a workspace artifact, return `output_artifact`.
- Defaults: `timeout=60` (today's 15 is too short for nmap), preset default when set, hard ceiling 3600. `timeout=None` permitted only with `stream=True` or `mode="start"`, so there is always live output and a cancel path.
- `mode="start|poll|send|kill"` uses `PtySessionManager.create_session` / `interact(action="wait"|"view"|"send"|"kill")` — and `create_session` must build argv through the same env mapper instead of `shell=True` on a raw string (`pty_session_manager.py:97-105`) before this is used.
- **Registration:** mandatory inside `register_all_default_tools`, carrying `risk_classifier`, `description` and `stream_output`; the `Tools_cyber` adapter at `:2607-2623` becomes register-only-if-absent. Assert at startup that the resolved `python_func` is the agent-bound one — otherwise a change in import order silently drops to the plugin version, which has no audit emission, no streaming, no cancel_event and no risk resolver.

**Gate:** new `tests/test_shell_exec_unified.py` (env resolution table, preset expansion, fallback pair behaviour with WSL absent, truncation, deadline kill, cancel). Registry still 207.

### Step 7 — Host-probed capability catalog
**Files:** `cyber_os/system_prompt.py`, the WSL state cache, `cyber_os/command_presets.py`

- One startup probe, cached next to `wsl_state`: `shutil.which` for native/cross-platform binaries; **one batched** `wsl.exe -- command -v nmap masscan dig ...` for all 18 WSL presets, not 18 calls, timeout-bounded ~5 s like `WSLDetector.detect_wsl`.

- Replace the hand-maintained `TOOL_RECIPES` at `system_prompt.py:72-82` with a generated `<command_capabilities>` section composed in `build_system_prompt` alongside the existing sections list (`:150`), with three buckets: available, **not installed on this host — do not attempt, and do not read their absence as a negative finding**, and unverified. The second bucket is the load-bearing half: it converts a silent "command not found" into prior knowledge, which is the only thing that stops "no open ports found" when nmap was simply absent.
- Do **not** list the dual-use tail (`hydra`, `sqlmap`, `metasploit`, `zap`) in the always-on index; reachable only through an explicit, auditable `command_catalog(query=...)` call. Today they are buried in a 20 k-token JSON blob; a readable prompt index would make them *more* salient than they are now, which is a posture change a defensive product should not make by accident.
- **Cached `absent` must never gate execution** — it informs the prompt only. A binary installed mid-session must stay reachable.

Token effect, for the record: `agent_runtime.py:172-175` dumps all 207 manifests via `json.dumps(indent=2)` into every system prompt (~100 tokens each, ~20.7 k standing). Dropping 58 removes ~5.8 k; the catalog section costs ~950 worst case, ~460 typical. Net ~23 % reduction with strictly more information.

**Gate:** new test asserting every preset id appears in the composed prompt, no preset id collides with a live registry tool name, and a simulated probe failure yields `unverified` rather than `absent`.

## 4. The single biggest risk, and the guard

**Risk: risk classification degrades from structural to heuristic, and `READ_ONLY` is the only tier that skips the human.**

`GuardrailManager.request_approval` (`cyber_tools.py:140-141`) is `if risk_level == RiskLevel.READ_ONLY and self.auto_approve_read_only: return True`, with `auto_approve_read_only` defaulting True, and `_wait_for_approval` (`cyber_agent.py:909`) duplicates the shortcut. Today `nmap {target}` could only ever be nmap — the fixed `command_template` is the *reason* a per-tool `READ_ONLY` label was ever trustworthy. Deleting the templates deletes that guarantee. After the collapse, `READ_ONLY` is a judgement about an arbitrary string, and one misclassification means `nmap 10.0.0.1; rm -rf /` executes unattended while the audit line reads `auto_approved / read_only`.

**Guard — four parts, all of which must land in Step 2, before the Step 6 removal:**

1. **Structural:** `READ_ONLY` is only ever produced by an exact allowlist rule matched on normalized argv[0] with constrained `allowed_flags`, applied to **every** segment, aggregated with `max()`. Prefix matching is never used. Unknown → `MODIFIES_SYSTEM`; unparseable or refuse-list hit → `DESTRUCTIVE`; a decode pass can never yield `READ_ONLY`.
2. **The concrete, gating test corpus** in `tests/test_command_classifier.py`, which is what makes this verifiable rather than aspirational:
   - For each of the 58 retired wrappers: its canonical expansion classifies **exactly** as that wrapper's pre-deletion `risk_level` (so the collapse provably preserves today's posture — the diff is 58 rules reproducing 58 existing decisions).
   - For each: the injected variant classifies `DESTRUCTIVE` — at minimum `target="1.1.1.1; rm -rf /"`, `target="x && Remove-Item -Recurse C:\\"`, `target="x | iex"`, `target="x > C:\\Windows\\System32\\drivers\\etc\\hosts"`, `powershell -EncodedCommand <b64>`, `bash -c '<anything>'`, `find . -exec rm {} \;`, and an unrecognized flag on an allowlisted binary (`nmap --script=http-put`).
3. **Fail-closed everywhere:** classifier exception → `DESTRUCTIVE`; malformed rules file → no allowlist → everything `MODIFIES_SYSTEM`; never "no rules, allow".
4. **No bypass around it:** the `threat_score >= 8` auto-approval hatch is closed for any tool carrying a `risk_classifier`, and `ApprovalEngine` session grants can satisfy `MODIFIES_SYSTEM` only — never `DESTRUCTIVE`, `unparseable`, or a refuse-list hit.

Runner-up risk, worth naming because it is a straight privilege escalation if Step 5 is split: the 10 specialist profiles are constrained today by literal `allowed_tools`, so a profile that may run only `nmap_scan` and `dig` would, after the collapse, hold `shell_exec` and therefore arbitrary command execution. `allowed_presets` enforced at the `shell_exec` entry point must land in the same commit as the profile edits.

Secondary note on `READ_ONLY`'s meaning: as modelled it means read-only to **host integrity**, not harmless. Exfiltration via `curl`, `Get-Content` on a private key, or scanning a third party's network all classify `READ_ONLY` and auto-approve. Do not let the tier name imply safety it does not carry; a confidentiality/egress axis is out of scope (see §5).

## 5. Deliberately not doing

1. **Not renaming `shell_exec`, and not adding a parallel `command_exec`.** A rename edits five consumer classes (`tool_map.py:33` for 68 markdown specialists, `compaction.py:51`, `profiles.py:108/125/239`, the AST test) for zero capability; a parallel tool leaves two ways to run a command, which is the duplication being removed. Extending in place is already additive, so track 5's green-intermediate-state argument is satisfied without the churn.
2. **Not retiring `shell_exec` or re-pointing `tool_map.py:33` `Bash`.** Its own blast radius, and the user's ask does not require it.
3. **Not deleting `windows_defender_scan`.** `tool_orchestrator.py:1288` is the only path that mints a critical finding from `threats_found`; collapsing it is a capability regression, not a rename.
4. **Not migrating the 68 markdown definitions.** All 68 `tools:` frontmatter lines declare Claude-style names only; the only wrapper-adjacent mentions are prose in `network-troubleshooter.md:62-76`, which no code reads. The specialists already assume the collapsed shape.
5. **Not touching the web frontend.** A bounded grep over `ui/hackerai` for `windows_defender_scan`, `nmap_scan`, `api/tools` returns zero hits; `/api/tools` at `api_server.py:376-388` is registry-driven and generic.
6. **Not doing track 4's python dedupe here** (−19) beyond the three items with shell-surface or fallback-edge entanglement (`service_enumeration`, `traceroute_simple`, `file_hash`). Phase D, separate PR: it changes return envelopes (`{success, output, error}` plugin shape vs bare dicts), which could silently break prompts, evals and subagent expectations that were never audited across the 68 definitions and 268 skills.
7. **Not resolving the 16 hardcoded `{"status": "simulated"}` registrations here.** Implement-vs-unregister is a policy call for the lead. Flagging the shape as urgent regardless: most return a *negative* verdict alongside `success=True` (`"dns_tunneling_detected": False`, `"beaconing_detected": False`, `"open_ports": []`, `"cert_valid": True`), so the agent reads "checked, nothing found". That defeats the already-landed "findings only from real tool results" fix from the other direction — no finding is minted, and the absence reads as an all-clear.
8. **Not merging `virustotal_hash_lookup` / `virustotal_ip_lookup`, `hash_identifier` with `file_hash`, or `file_tool` with `workspace_read_file`.** Verified genuinely distinct: different endpoints (both named in `profiles.py:46-47`, with `enrich_artifact` already routing polymorphically); hash-string classification vs hashing a path; and differing `risk_level`, which is load-bearing since one is auto-approved and the other prompts.
9. **Not using an LLM to classify command risk.** The input is attacker-influenceable by construction, non-deterministic, and unauditable — "why was this auto-approved" needs a replayable answer. It may enrich the operator-facing `reason` text; it must not produce `level`.
10. **Not routing `mode="run"` through `PtySessionManager`.** It uses `shell=True` on a raw string with no env mapping and no deadline kill; `execute_system_command` already has the `output_callback` and `cancel_event` plumbing this design depends on.
11. **Not building a complete shell parser or multi-layer decoder.** One decode pass, then refuse. Multi-layer encodings surface as undecodable → `DESTRUCTIVE`, which is the safe direction; the approval card must say plainly that the payload could not be decoded rather than showing a partial decode that reads as reassuring.
12. **Not adding a confidentiality/egress risk axis.** Real gap (see §4), out of scope here.
13. **Not auto-learning allowlist rules from observed traffic.** Repeated `undecidable` entries are candidates for human-reviewed rules only; auto-learning an allowlist is how an attacker installs their own rule.
14. **Not touching the `AuditLogger` read-modify-write or `generate_incident_report`'s fabricated event.** Owned by the lead. Dependency worth stating: the classifier's `command_classified` events land in that same logger, so the concurrency fix should precede or accompany Step 4 or the new events will be dropped under load exactly when they matter.
