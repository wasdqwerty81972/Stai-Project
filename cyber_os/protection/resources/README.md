# Bundled demonstration signature

`demo-manifest.json` is an Ed25519-signed, versioned rule package containing
only the SHA-256 signature for the harmless EICAR anti-malware test file. Its
purpose is to verify scan, alert, and quarantine behavior during development.
It is not a general malware signature database and does not make SVS Cyber a
replacement for Microsoft Defender or a commercial antivirus product.

On Windows, the service also watches the enrolled user's existing Downloads,
Desktop, and Local Temp folders. It waits briefly after file changes, then
scans the file against the signed package. This is best-effort post-write
coverage of those folders; it does not intercept file opens or block execution
before a write completes. Windows audit events can provide additional evidence
when the relevant audit policy is already enabled.

High-confidence signed block rules can trigger automatic quarantine. AI
classifications and confidence scores are advisory and cannot create a block
verdict or authorize quarantine. A driver that is absent, unsigned, or not connected
is shown as unavailable/degraded in status; no kernel-level protection is
claimed in that state.

For a safe demo, use the EICAR test file only and expect Microsoft Defender or
another installed antivirus to detect it first. Do not download or install a
live malware sample on a daily-use machine.

The matching private signing key is not stored in this repository. Production
signature updates must be generated by a separately controlled signing
process and distributed through an authenticated update channel.

The separate `windows_protection/installer/rules` tree contains signed YARA
Forge core and extended packages with 898 and 8,583 source-declared rules,
respectively. Imported community rules are observation-only; a match does not
automatically block or quarantine. A package on disk is not evidence that an
installed service has loaded it. Check the service's authenticated rule metadata.

Additional unsigned, source-attributed hash candidates live in
`cyber_os/protection/rule_candidates`; inert rule examples live in
`examples/reference-rules`. These require review and external signing before
activation. Never replace a trusted public key merely to load an unsigned rule.
