# Mobile response boundaries

## Response pipeline

`Supported Android signal → collector → durable local event → deterministic local rule → finding + notification → optional user-reviewed investigation`

Persist an event before exposing it to the Flutter UI. A sensor event may trigger local rules automatically only inside the feature, permission, background-execution, and resource limits the user enabled. The AI provider is not on the immediate response path.

## Consumer application

The consumer build may automatically:

- Deduplicate and normalize collected local events.
- Evaluate versioned deterministic rules against permitted evidence.
- Create an evidence-linked local finding and notify the user.
- Apply a preconfigured, narrow, reversible network rule only after the user separately enables the VPN and authorizes that policy. Any later block must have an expiry, audit record, visible VPN state, and undo path.

It must not claim universal or continuous visibility. Android limits background execution, and most capabilities are snapshots, bounded observations, or require special user access. The local VPN can only affect traffic routed through it; it cannot stop a process or remove malware. The VPN module remains out of the initial release.

The app must not automatically uninstall, force-stop, suspend, or change permissions for another app; delete user files; silently enable a VPN; decrypt HTTPS; or execute arbitrary commands generated by AI. Consumer applications run in Android's app sandbox, while package suspension and managed enforcement require authorized enterprise device policy.

## AI and evidence privacy

Local rules and findings must work offline and without credentials. AI may explain or correlate user-selected evidence. Before an external request, show the provider, exact evidence preview, and personal-data redactions, then require explicit confirmation. AI text is advisory and cannot become evidence without an independent source.

User-supplied API keys stored by Android Keystore are encrypted at rest, but a key used directly by a mobile client can still be exposed through a compromised or instrumented runtime. Direct provider calls are therefore an internal-use feature until a distribution-safe proxy or on-device model is selected. Never embed a provider key in the APK.

## Enterprise boundary

Enterprise logging and enforcement are separate from consumer features. They require valid device-owner, organization-managed profile, or delegated provisioning, and the exact supported scope must be shown. An ordinary installation never advertises enterprise capabilities as active.
